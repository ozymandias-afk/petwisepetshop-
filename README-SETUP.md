# PetWise website — setup and deployment

This project keeps the existing PetWise red visual theme, logo, Arabic/English language switcher, RTL layout, and the current Home, Shop, Services, About, and Contact pages. The project is built with Next.js App Router and is intended to deploy as a Node-enabled Next.js site (Netlify's Next.js adapter or Vercel), not as a single static HTML file.

## 1. Run locally

1. Install Node.js 20.9+ and npm.
2. Copy `.env.example` to `.env.local` and fill in the required values.
3. Run `npm install`.
4. Run `npm run dev`, then open `http://localhost:3000`.

## 2. Configure Supabase

1. Create a Supabase project.
2. Open SQL Editor and run `supabase/schema.sql`. This creates categories, products, customers, orders, order_items, admin_users, RLS policies, and image/proof storage buckets. It also seeds the eight existing placeholder products and categories.
3. In Project Settings → API, copy the project URL and public anon key into `NEXT_PUBLIC_SUPABASE_URL` and `NEXT_PUBLIC_SUPABASE_ANON_KEY`; set `SUPABASE_URL` to the same URL and put the service-role key only in `SUPABASE_SERVICE_ROLE_KEY` on the server/deployment platform.
4. In Supabase Authentication, create the two approved admin email/password users (the shop owner and your own account). Then insert their exact auth user IDs and emails into `public.admin_users` using the SQL editor. Example:
   ```sql
   insert into public.admin_users(user_id,email)
   values ('AUTH_USER_UUID_1','owner@example.com'),
          ('AUTH_USER_UUID_2','you@example.com');
   ```
   Do not add anyone else. The RLS policies authorize admin access only for IDs in this allowlist.
5. The `product-images` bucket is public so product photos can be served by the shop. The `payment-proofs` bucket is private and is written by the server only.

## 3. Email notifications

Email sending uses Resend when `RESEND_API_KEY`, `ORDER_EMAIL_FROM`, and `SHOP_NOTIFICATION_EMAIL` are configured. Verify the sender domain in Resend first. If these variables are missing, orders can still be saved but emails will not be sent. The order confirmation email is sent when the customer entered an email address.

## 4. Payments

- Cash on delivery / pay at pickup is available.
- CliQ/bank transfer accepts a transfer reference and an optional screenshot. Set `NEXT_PUBLIC_CLIQ_ALIAS`, `NEXT_PUBLIC_BANK_IBAN`, and `NEXT_PUBLIC_BANK_ACCOUNT_NAME` to the actual payment details before taking live orders; these are displayed publicly in checkout, so use only details intended for customers. No bank details are fabricated.
- Card checkout is deliberately disabled until a gateway that supports Jordan and JOD is selected, merchant credentials are supplied, and server-side payment-session creation plus webhook verification are implemented. `lib/payments/provider.ts` defines the provider interface; the environment variable names are placeholders only. Never trust a browser redirect as proof of payment.

## 5. URLs, SEO and deployment

- Set `NEXT_PUBLIC_SITE_URL` to the canonical public site origin. It is used for WhatsApp messages, product Open Graph URLs, structured data, sitemap, and robots.
- `/ar/...` and `/en/...` paths are rewritten to the existing pages and set the language cookie. The existing switcher continues to work.
- `/sitemap.xml` and `/robots.txt` are generated by Next.js. Admin and checkout are disallowed in robots.
- Deploy the whole project directory, not just `index.html`; this uses Next.js server routes for secure orders and metadata.
- Configure all environment variables in the hosting provider's project settings, then redeploy.
- The WhatsApp order destination is `+962 7 9560 6749`. WhatsApp links are prefilled; the customer must press Send. The site cannot send WhatsApp messages automatically without a WhatsApp Business API integration.

## 6. Important security notes

- Never commit `.env.local`, Supabase service-role keys, Resend keys, or payment secrets.
- Public visitors can read active catalog products/categories only. Customer/order records have RLS and are accessible to approved admins; order writes go through the server API.
- The current catalog page uses database products when configured, with the bundled catalog as a development fallback.
- Before production, test a complete order in a staging Supabase project, review delivery fees/stock rules, verify email sender identity, and configure backups and privacy/retention practices.
